Learn to schedule local notifications, test mobile applications, handle errors, and prepare an Expo app for deployment.

1. Learning Objectives

By the end of the instructional week, students should be able to:

  1. Explain the difference between local and remote push notifications.
  2. Schedule and receive a local notification with Expo Notifications.
  3. Request notification permission and handle a denied request appropriately.
  4. Use basic logging, error handling, and a test checklist to verify an application.
  5. Describe the constraints of background tasks and mobile operating-system permissions.
  6. Configure application metadata and describe the steps for creating an installable build.
Prerequisites: Familiarity with React components, hooks, Expo, navigation, fetching JSON data, AsyncStorage, camera, and location permissions.

4. Complete Code Example: Local Reminder App

This demonstration requests notification permission, schedules a reminder five seconds into the future, and displays the scheduling result. It also includes basic error handling.

import React, { useEffect, useState } from 'react';
import { Alert, Button, Platform, SafeAreaView,
  StyleSheet, Text, View } from 'react-native';
import * as Notifications from 'expo-notifications';

// Display notifications while the app is open.
Notifications.setNotificationHandler({
  handleNotification: async () => ({
    shouldShowBanner: true,
    shouldShowList: true,
    shouldPlaySound: true,
    shouldSetBadge: false,
  }),
});

export default function App() {
  const [status, setStatus] = useState('No reminder scheduled');

  useEffect(() => {
    async function configureAndroid() {
      if (Platform.OS === 'android') {
        await Notifications.setNotificationChannelAsync('reminders', {
          name: 'Reminders',
          importance: Notifications.AndroidImportance.DEFAULT,
        });
      }
    }
    configureAndroid().catch(console.error);
  }, []);

  async function scheduleReminder() {
    try {
      const permission = await Notifications.requestPermissionsAsync();
      if (!permission.granted) {
        setStatus('Notifications permission denied');
        Alert.alert('Permission needed',
          'Enable notifications in device settings to receive reminders.');
        return;
      }

      const id = await Notifications.scheduleNotificationAsync({
        content: {
          title: 'Mobile Development Reminder',
          body: 'Your local notification is working!',
          sound: 'default',
        },
        trigger: {
          type: Notifications.SchedulableTriggerInputTypes.TIME_INTERVAL,
          seconds: 5,
          channelId: Platform.OS === 'android' ? 'reminders' : undefined,
        },
      });
      setStatus(`Reminder scheduled: ${id.slice(0, 8)}...`);
    } catch (error) {
      console.error(error);
      setStatus('Unable to schedule reminder');
      Alert.alert('Error', String(error.message || error));
    }
  }

  return (
    <SafeAreaView style={styles.screen}>
      <View style={styles.card}>
        <Text style={styles.title}>Reminder Demo</Text>
        <Text style={styles.text}>{status}</Text>
        <Button title="Notify Me in 5 Seconds"
          onPress={scheduleReminder} />
      </View>
    </SafeAreaView>
  );
}

const styles = StyleSheet.create({
  screen: { flex: 1, justifyContent: 'center', padding: 24,
    backgroundColor: '#eef4fa' },
  card: { backgroundColor: 'white', padding: 24,
    borderRadius: 12, gap: 18 },
  title: { fontSize: 26, fontWeight: 'bold' },
  text: { fontSize: 16 },
});

Expected result: The app displays a button. After the student grants permission and taps the button, a local notification is scheduled. Students should verify both foreground and background behavior.

Instructor note: Expo notification API details and device support can change with SDK versions. The example uses the current typed time-interval trigger pattern; check the official documentation if using a different SDK. Android exact scheduling behavior and iOS notification display can vary. A local reminder does not require a push token or a server.

5. Testing, Debugging, and Background Tasks

Testing checklist

  1. Launch the app without a runtime error.
  2. Tap the reminder button and accept notification permission.
  3. Confirm that a notification appears after the scheduled delay.
  4. Repeat the test with the app in the background.
  5. Deny permission and confirm the app explains what happened without crashing.
  6. Test a slow or unavailable internet connection if the app uses an API.
  7. Restart the app and verify any stored data is still available.
  8. Check the terminal and device logs for warnings and errors.

Debugging strategies

// Log useful values during development
console.log('Notification permission status:', permission.status);

// Handle an asynchronous operation safely
try {
  const response = await fetch('https://jsonplaceholder.typicode.com/users');
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  const users = await response.json();
  console.log('Loaded users:', users.length);
} catch (error) {
  console.error('API request failed:', error);
}

Background tasks: conceptual overview

Background work is not guaranteed to run at an exact time. Mobile operating systems restrict background execution to protect battery life and privacy. Students should distinguish scheduled local notifications from background tasks that fetch or process data. A notification can be scheduled without continuously running JavaScript in the background.

Optional exploration: Read the Expo BackgroundTask and TaskManager documentation and explain why a recurring background sync cannot be relied on to execute every minute. Implementing background tasks is optional for this course.

6. Preparing for Deployment

Update app.json with a meaningful name, slug, and application identifiers. Use unique identifiers that you control; the values below are examples only.

{
  "expo": {
    "name": "Mobile Reminder Demo",
    "slug": "mobile-reminder-demo",
    "version": "1.0.0",
    "ios": { "bundleIdentifier": "edu.example.mobilereminder" },
    "android": { "package": "edu.example.mobilereminder" }
  }
}

For an optional installable build, follow the official EAS Build setup instructions:

npm install --global eas-cli
eas login
eas build:configure
# Example: Android build for testing; configure a suitable
# preview profile and credentials first.
eas build --platform android --profile preview
Important: An EAS preview build is not the same as publishing to an app store. Build profiles, account access, signing credentials, and device provisioning vary by platform. Students are not required to purchase developer accounts or publish an app to earn full credit.

  1. Create the MobileReminderDemo project and install expo-notifications.

  3. Modify the notification title and body to reflect a school, sports, or personal reminder.

  6. Record at least three test cases with expected and actual results.
  7. Show the instructor a working demo or submit a short screen recording.

Deliverable: Screenshot or screen recording, updated App.js, and a brief test log.

8. Discussion Board: Notifications, Privacy, and App Reliability

Prompt: Mobile applications can send reminders, access location, use the camera, and store personal data. When are these features useful, and when do they become intrusive? Compare two real-world apps and explain how developers should request permissions, minimize unnecessary data collection, and prevent excessive notifications.

Requirements: Initial post of 200–300 words; respond thoughtfully to at least two classmates (75–100 words each). Include one concrete design recommendation.

Discussion grading (20 points): Analysis 10; examples and recommendation 5; peer responses 5.
