1. Project Overview

Develop an original, functional mobile app using React Native and Expo. You may choose a useful real-world concept: sports stats, fitness logging, campus events, recipe planner, travel journal, volunteer tracker, inventory, or another instructor-approved idea. Your application must demonstrate the mobile development skills taught throughout the semester. A static mockup or tutorial copied without meaningful customization is not sufficient.

Learning outcomes

  • Plan a complete app with a target audience, user stories, and screen designs.
  • Implement a usable interface with navigation and interactive state.
  • Retrieve remote JSON data from an API and persist user-generated data locally.
  • Use native device functionality with responsible permission handling.
  • Test, debug, document, and prepare an app for distribution.
Individual project: Each student must author and explain their own code. Third-party libraries and AI assistance may be used if disclosed and understood; do not submit someone else's finished application.

2. Minimum Technical Requirements

  1. React Native + Expo: a running application with a sensible folder structure and readable components.
  2. At least four functional screens: for example Home, Browse, Detail, Saved/Journal, and Settings. Include working navigation.
  3. State and user interaction: inputs, buttons, lists, conditional views, and appropriate validation.
  4. External API: make at least one real HTTP request, parse JSON, display meaningful results, and handle loading, empty, and error states. Use an API you are authorized to access; do not embed private keys.
  5. Persistent local storage: save and restore meaningful user data with AsyncStorage or another suitable storage method.
  6. Native device feature: integrate at least one of camera, photo library, GPS/location, or notifications. Request permissions where needed, explain their purpose, and handle refusal without crashing.
  7. Notifications: implement a working local notification or, if genuinely unsuitable for the app, propose an instructor-approved equivalent native feature. Push server infrastructure is not required.
  8. Testing: demonstrate the main flows on a physical device or simulator; record at least six test cases including failure scenarios.
  9. Accessibility and UX: legible labels, touch-friendly controls, useful feedback, and clear navigation.
  10. Documentation: README with installation, run commands, features, dependencies, known limitations, screenshots, and attribution.

Examples: A sports app could show live API-backed team information, let users save favorite teams, schedule game reminders, and attach photos to a game-day journal. A travel journal could use a places API, GPS check-ins, photo capture, local entries, and reminders.

3. Step-by-Step Development Workflow

Phase A — Plan and design

  1. Write a one-paragraph app proposal describing the audience, problem, and main features.
  2. Write at least five user stories, e.g., “As a user, I want to save favorite locations so I can revisit them.”
  3. Sketch or wireframe at least four screens and draw a navigation map.
  4. Select a public API and explain its data, rate limits, and authentication requirements.
  5. Identify what will be stored locally and which device permissions are necessary.

Phase B — Create the Expo project

npx create-expo-app@latest MyCapstoneApp
cd MyCapstoneApp
npx expo start

Open the folder in Visual Studio Code. Follow the current Expo project template's navigation structure; do not assume all templates use the same entry file. Run the app in Expo Go where compatible, or use a development build when required by native libraries.

Phase C — Add course technologies

npx expo install @react-native-async-storage/async-storage
npx expo install expo-location expo-camera expo-notifications

Install only the device packages your app actually needs. Build screens and navigation first; then integrate API calls, local storage, native features, and notifications. Avoid requesting permissions on launch unless necessary.

Phase D — Test and refine

  1. Confirm every screen can be reached and navigated away from.
  2. Test online and offline behavior, empty API results, and failed requests.
  3. Restart the app and verify saved information remains available.
  4. Deny device permissions and confirm the app remains usable or explains what is unavailable.
  5. Test invalid inputs and repeated button taps.
  6. Check readable text, layout, and touch targets on more than one screen size if possible.

Phase E — Prepare a release-ready app

  1. Set an app name, icon, splash screen, version, and unique platform identifiers.
  2. Review all dependencies, remove secrets, and use HTTPS for remote requests.
  3. Prepare a truthful privacy policy and store data disclosures if you pursue publication.
  4. Produce a final demo and complete documentation.

4. Required Submission Package

  • Source code: GitHub repository URL or ZIP containing source and configuration, excluding node_modules and credentials.
  • README: project summary, setup instructions, run commands, feature inventory, API source, permission explanations, and known issues.
  • Design evidence: proposal, five user stories, four wireframes, and navigation diagram.
  • Testing report: at least six test cases with expected/actual results and fixes.
  • Visual evidence: screenshots of at least four screens.
  • Demo: 5–8 minute recorded or live demonstration, including a working API request, persistence after restart, native device functionality, and notification behavior.
  • Reflection: 300–500 words describing the hardest problem, solution, lessons learned, and future enhancements.
Store publication is optional. Students can earn all 200 base points without paying for developer accounts or releasing an app publicly.

6. Optional Bonus: Publish to an App Store

Publishing is a professional extension, not a requirement. Store fees, identity verification, review policies, and release schedules are controlled by Apple and Google. Never pay a fee solely to satisfy the class assignment. Discuss any school-managed developer account option with the instructor first. As of November 2026, Apple lists a US $99 annual developer membership; Google Play lists a US $25 one-time registration fee. Verify fees before enrolling.

Common preparation for both stores

  1. Finish the app and test on real hardware where possible.
  2. Create a unique reverse-domain identifier, e.g. edu.example.studentapp (replace with an identifier you control).
  3. Prepare a high-quality icon, screenshots, short/long descriptions, contact email, support information, and privacy policy.
  4. Explain camera/location/notification use accurately and complete all applicable privacy and data-safety disclosures.
  5. Install Expo's build tooling and log in:
npm install --global eas-cli
eas login
eas build:configure

Configure app.json or app.config.js with appropriate identifiers. Example (merge into your existing configuration; do not overwrite other Expo settings):

{
  "expo": {
    "name": "My Capstone App",
    "slug": "my-capstone-app",
    "version": "1.0.0",
    "ios": { "bundleIdentifier": "edu.example.mycapstone" },
    "android": { "package": "edu.example.mycapstone" }
  }
}

Apple App Store — step by step

  1. Enroll in the Apple Developer Program or obtain authorized access to an eligible organizational account. Enable two-factor authentication and complete verification.
  2. Sign in to App Store Connect; under Apps, create a new app record with its name, primary language, bundle identifier, and SKU. Confirm the identifier matches your Expo configuration.
  3. Review app permissions, privacy policy, content ratings, and screenshots. Ensure the app does not contain placeholder content or broken features.
  4. Build an iOS release using Expo's cloud build service:
eas build --platform ios --profile production
  1. Follow prompts to configure signing certificates and provisioning profiles; Expo can manage credentials when authorized.
  2. Upload the build:
eas submit --platform ios
  1. Wait for processing in App Store Connect. The uploaded build can appear in TestFlight; TestFlight availability is not public App Store publication.
  2. Complete the App Store version listing, screenshots, privacy answers, age rating, support information, and review notes. Provide demo credentials if login is required.
  3. Select the processed build, choose Submit for Review, and respond to any reviewer questions or rejection feedback.
  4. After approval, choose the appropriate release option and verify the public App Store listing. Save its URL and screenshot as bonus evidence.

Official Expo iOS submission instructions · Apple App Review Guidelines

Google Play Store — step by step

  1. Create a Google Play Console developer account, pay the registration fee if applicable, and complete identity verification.
  2. Choose Create app and enter the app name, language, app/game designation, and free/paid setting.
  3. Complete the dashboard's required declarations, including app access, ads, target audience, content rating, Data safety, privacy policy, and any relevant permissions.
  4. Build a signed Android App Bundle (.aab):
eas build --platform android --profile production
  1. For the first release, either upload the .aab manually to an appropriate testing track in Play Console, or configure a Google service account for Expo Submit and run:
eas submit --platform android
  1. Complete the store listing, including screenshots, descriptions, category, contact information, and disclosures. An upload alone does not publish the app.
  2. Use internal or closed testing to identify bugs. Important: personal developer accounts created after November 13, 2023 generally must complete a closed test with at least 12 opted-in testers for 14 continuous days before applying for production access. Follow the current Play Console requirements for your account.
  3. When eligible, request production access, create or promote a production release, resolve policy warnings, and submit for review.
  4. Once approved and rolled out, verify the public Google Play listing and record its URL and screenshot.

Official Expo Android submission instructions · Manual first-release walkthrough · Google Play developer help

Privacy and safety: Do not publish real classmates' photos, GPS coordinates, personal information, copyrighted graphics, or proprietary data without permission. Do not commit Apple certificates, service-account JSON files, API secrets, or other credentials to GitHub. Review store policies before submission. Store review and testing can extend beyond the course deadline.

For example, a student who builds, tests, submits, and publishes to one store earns 25 points; publishing on the second store reaches the 30-point cap. Fairness: Students who cannot afford developer accounts may still earn full base credit. Obtain approval before using this alternative.
