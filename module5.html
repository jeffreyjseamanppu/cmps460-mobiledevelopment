Module Overview

In Module 4, we learned how to build applications containing multiple screens and how to move information between those screens using React Navigation.

We will now begin working with larger collections of information. Most real-world mobile applications need to display, modify, and store data. A shopping application might maintain a shopping cart, a fitness application might track workouts, and a task application might maintain a list of things the user needs to complete.

In this module, we will learn how to represent collections using TypeScript arrays and objects, display those collections using FlatList, and allow users to add and remove information.

We will also introduce persistent local storage using AsyncStorage. This will allow our applications to remember information even after the application has been closed.

Key Concept: Application state stores information while an application is running. Persistent storage allows information to remain available after the application is closed and reopened.

Lecture: Working with Data in React Native

1. Arrays and Objects

Mobile applications frequently work with collections of related information. In TypeScript, we can represent these collections using arrays and objects. 

const tasks = [
    {
        id: "1",
        title: "Complete Mobile Programming Lab",
        completed: false
    },
    {
        id: "2",
        title: "Study React Native",
        completed: true
    }
];

Each object represents one task. The array stores the complete collection of tasks.

2. Creating a TypeScript Interface

TypeScript allows us to define the structure that each object should follow. 

interface Task {
    id: string;
    title: string;
    completed: boolean;
}

This helps prevent errors by ensuring every task contains the expected information.

3. Storing Collections in State

Collections can be stored using the React useState hook. 

const [tasks, setTasks] = useState<Task[]>([]);

In this example, the application begins with an empty collection of tasks.

4. Adding Items to a Collection

React state should not be modified directly. Instead, we create a new array containing the existing items and the new item. 

const addTask = (taskName: string) => {

    const newTask = {
        id: Date.now().toString(),
        title: taskName,
        completed: false
    };

    setTasks([...tasks, newTask]);
};

5. Displaying Data with FlatList

React Native provides the FlatList component for efficiently displaying collections of information. 

<FlatList
    data={tasks}

    keyExtractor={(item) => item.id}

    renderItem={({ item }) => (
        <Text>{item.title}</Text>
    )}
/>

FlatList contains three important properties:

  • data – The collection that should be displayed.
  • keyExtractor – Provides a unique identifier for each item.
  • renderItem – Determines how each item appears on the screen.

6. Why Unique IDs Matter

React needs a way to uniquely identify each item displayed in a list. This allows React to efficiently determine which items have been added, removed, or changed. 

{
    id: "12345",
    title: "Finish Homework",
    completed: false
}

The id should be unique for each item.

7. Removing Items

The JavaScript filter() method can be used to create a new array that excludes an item. 

const deleteTask = (id: string) => {

    setTasks(
        tasks.filter(task => task.id !== id)
    );

};

8. Handling an Empty List

Applications should provide feedback when there is no information to display. 

<FlatList
    data={tasks}

    ListEmptyComponent={
        <Text>
            No tasks have been added.
        </Text>
    }

    renderItem={({ item }) => (
        <Text>{item.title}</Text>
    )}
/>

9. Temporary State vs. Persistent Storage

There is an important limitation to React state. If the application closes, the information stored in state disappears.

Consider a user creating five tasks. If those tasks exist only in useState, restarting the application would return the application to an empty list.

Real applications often need information to remain available between sessions.

Examples include:

  • User preferences
  • Tasks
  • Favorite items
  • Shopping lists
  • Notes
  • Application settings

10. AsyncStorage

AsyncStorage provides a simple way to save key-value information locally on a user's mobile device.

Install AsyncStorage from your project folder:

npx expo install @react-native-async-storage/async-storage

Then import it into your application:

import AsyncStorage from '@react-native-async-storage/async-storage';

11. Saving Data

AsyncStorage stores strings. Arrays and objects must therefore be converted into a string before they can be stored.

JavaScript provides JSON.stringify() for this purpose. 

const saveTasks = async (tasks: Task[]) => {

    try {

        await AsyncStorage.setItem(
            "tasks",
            JSON.stringify(tasks)
        );

    } catch (error) {

        console.log("Error saving tasks:", error);

    }
};

12. Loading Saved Data

When data is retrieved, JSON.parse() converts the stored string back into an array or object. 

const loadTasks = async () => {

    try {

        const savedTasks =
            await AsyncStorage.getItem("tasks");

        if (savedTasks !== null) {

            setTasks(
                JSON.parse(savedTasks)
            );

        }

    } catch (error) {

        console.log("Error loading tasks:", error);

    }
};

13. Loading Data When the App Starts

The React useEffect hook can be used to load saved information when a component first appears. 

useEffect(() => {

    loadTasks();

}, []);

The empty dependency array tells React to run this code when the component initially loads.

14. Saving When Data Changes

We can also use useEffect to save information whenever the task collection changes. 

useEffect(() => {

    saveTasks(tasks);

}, [tasks]);
Important: AsyncStorage is useful for learning local persistence and for storing relatively small amounts of application data. Later in the course, we will explore applications that retrieve information from external services and APIs.
