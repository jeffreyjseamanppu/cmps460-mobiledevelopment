Module Overview

Modern mobile applications often depend on external services for information such as weather, products, social posts, and account details. In this module, students learn to request information from a REST API, interpret JSON responses, and present remote data in a React Native interface. Students will also practice handling slow networks, unsuccessful responses, and loading states.

Prerequisites: Basic React Native components, props, state with useState, lists using FlatList, and an existing Expo/TypeScript project.

Module deliverables: Complete the guided lab, submit the API Integration Homework (100 points), and participate in the discussion (50 points). Follow the due dates posted in the course LMS.

Learning Objectives

By the end of this module, students will be able to:

  1. Describe an application programming interface (API) and the purpose of REST APIs.
  2. Distinguish between GET, POST, PUT, PATCH, and DELETE HTTP methods.
  3. Identify endpoints, request headers, status codes, and JSON response structures.
  4. Use fetch() and async/await in a React Native TypeScript project.
  5. Define TypeScript interfaces that describe API response objects.
  6. Display retrieved data with FlatList and appropriate keys.
  7. Show loading, error, and empty states and allow users to retry or refresh.
  8. Explain tradeoffs between local storage and data retrieved from an API.

Lecture: APIs and External Data

1. What Is an API?

An API is a defined way for software systems to communicate. A mobile application can request information from a remote service without needing direct access to the service's database. A REST API commonly exposes resources through URLs called endpoints.

Example endpoint: https://jsonplaceholder.typicode.com/posts. This endpoint returns sample post objects in JSON format.

2. HTTP Methods and Status Codes

MethodTypical purposeExample
GETRetrieve dataLoad a list of posts
POSTCreate a resourceSubmit a new post
PUTReplace a resourceReplace a saved profile
PATCHPartially update a resourceChange a display name
DELETERemove a resourceDelete a post

Common HTTP status codes include 200 (OK), 201 (Created), 400 (Bad Request), 401 (Unauthorized), 404 (Not Found), and 500 (Internal Server Error).

3. Understanding JSON

JSON (JavaScript Object Notation) is a text format for exchanging structured information. A response can contain objects, arrays, strings, numbers, booleans, and null values.

{
  "userId": 1,
  "id": 1,
  "title": "My first API post",
  "body": "This content came from a remote API."
}

4. Asynchronous Programming

Network requests can take time. async/await allows the application to wait for a request without blocking the user interface. A try/catch/finally structure separates successful results, failures, and cleanup.

async function loadPosts(): Promise<void> {
  try {
    const response = await fetch(
      'https://jsonplaceholder.typicode.com/posts'
    );
    if (!response.ok) {
      throw new Error(`HTTP ${response.status}`);
    }
    const data = await response.json();
    console.log(data);
  } catch (error) {
    console.error('Unable to load posts:', error);
  }
}

Important: fetch() does not automatically reject for HTTP errors such as 404 or 500. Check response.ok yourself.

5. TypeScript Interfaces

Interfaces describe the expected structure of data and help catch mistakes while developing.

interface Post {
  userId: number;
  id: number;
  title: string;
  body: string;
}

TypeScript types do not validate the contents of a response at runtime. In production apps, validate untrusted responses before relying on their structure.

6. React Native State and Data Display

Use useState to store the returned data and track loading and error conditions. Use useEffect to start a request when a screen first appears. Use FlatList to render collections efficiently. Add a retry button and pull-to-refresh so users can recover from network problems.

7. Security and Reliability Considerations

  • Prefer HTTPS endpoints.
  • Never embed private API secrets directly in client-side mobile code.
  • Handle missing data, timeouts, and offline conditions gracefully.
  • Do not assume a successful network response means the data is valid.
  • Use appropriate authentication when accessing private resources.

Part B — Implement the Screen

Replace the main screen contents with this complete example:

import React, { useCallback, useEffect, useState } from 'react';
import {
  ActivityIndicator,
  Button,
  FlatList,
  SafeAreaView,
  StyleSheet,
  Text,
  View,
} from 'react-native';

interface Post {
  userId: number;
  id: number;
  title: string;
  body: string;
}

export default function App() {
  const [posts, setPosts] = useState<Post[]>([]);
  const [loading, setLoading] = useState(true);
  const [refreshing, setRefreshing] = useState(false);
  const [error, setError] = useState<string | null>(null);

  const fetchPosts = useCallback(async (isRefresh = false) => {
    if (isRefresh) setRefreshing(true);
    else setLoading(true);
    setError(null);

    try {
      const response = await fetch(
        'https://jsonplaceholder.typicode.com/posts'
      );
      if (!response.ok) {
        throw new Error(`Request failed: ${response.status}`);
      }
      const data: Post[] = await response.json();
      if (!Array.isArray(data)) {
        throw new Error('Unexpected API response');
      }
      setPosts(data);
    } catch (err) {
      setError(err instanceof Error ? err.message : 'Unknown error');
    } finally {
      setLoading(false);
      setRefreshing(false);
    }
  }, []);

  useEffect(() => {
    void fetchPosts();
  }, [fetchPosts]);

  return (
    <SafeAreaView style={styles.container}>
      <Text style={styles.heading}>API Post Viewer</Text>
      {loading ? (
        <ActivityIndicator size="large" accessibilityLabel="Loading posts" />
      ) : error ? (
        <View>
          <Text style={styles.error}>{error}</Text>
          <Button title="Retry" onPress={() => void fetchPosts()} />
        </View>
      ) : (
        <FlatList
          data={posts}
          keyExtractor={(item) => String(item.id)}
          renderItem={({ item }) => (
            <View style={styles.card}>
              <Text style={styles.title}>{item.title}</Text>
              <Text>{item.body}</Text>
            </View>
          )}
          refreshing={refreshing}
          onRefresh={() => void fetchPosts(true)}
          ListEmptyComponent={<Text>No posts available.</Text>}
        />
      )}
    </SafeAreaView>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, padding: 18, backgroundColor: '#f5f7fa' },
  heading: { fontSize: 25, fontWeight: 'bold', marginBottom: 16 },
  card: { backgroundColor: '#fff', padding: 14, borderRadius: 8,
          marginBottom: 12 },
  title: { fontSize: 17, fontWeight: 'bold', marginBottom: 7 },
  error: { color: '#a51b1b', marginBottom: 12 },
});

Scenario

Choose a free public API that fits your application idea, or use JSONPlaceholder if your project does not yet have a suitable API. Discussion: Local Storage vs. Cloud-Based API Data

Total: 50 points

Discussion Prompt

Mobile applications can store data directly on a device or retrieve it from a remote API. Both approaches have benefits and limitations. Imagine you are designing a mobile app that tracks information such as personal tasks, inventory, class assignments, or event registrations.

In your initial post, address all of the following questions:

  1. What are two advantages and two disadvantages of retrieving information from an external API instead of storing it only on the device?
  2. How do internet connectivity, performance, privacy, and data consistency affect your decision?
  3. For your semester mobile application, what information would you store locally and what information would you retrieve remotely? Explain your reasoning with a specific example.
  4. How should your app respond if an API is unavailable or returns an error?

Responses such as “I agree” or “Good post” without substantive explanation do not earn full credit. Use respectful, professional language and cite outside sources when appropriate.
