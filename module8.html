Lecture: Navigation and Mobile UX

1. Navigation Patterns

Stack navigation follows a sequence of screens (for example, Home → Task Details → Edit Task). A back action returns to the previous screen. Tab navigation provides direct access to major areas of an application, such as Home, Tasks, and Settings. Many production apps combine both approaches.

2. Screen Parameters and Type Safety

Navigation parameters allow one screen to identify a selected record. TypeScript can define valid routes and the data each route accepts, reducing runtime errors. Avoid passing entire large objects when a stable record ID is sufficient.

3. Reusable Components

Buttons, headers, input fields, and task cards should share consistent styling and behavior. Reusable components reduce duplicate code and improve maintainability.

4. Form Validation and Feedback

Validate required inputs, show clear error messages, and provide feedback after saving. Do not silently discard user entries. Disable or guard against duplicate submissions when appropriate.

5. User Experience and Accessibility

Good UX emphasizes clear navigation, readable typography, adequate touch targets, meaningful labels, sufficient contrast, predictable back behavior, and useful empty states. Test with a screen reader where possible and avoid relying on color alone to communicate status.

6. Persistent Data Across Screens

Navigation controls where users go; application state controls what users see. Store tasks in shared state or reload them when a screen receives focus. Save changes to AsyncStorage and handle failures gracefully.

Example: Typed Navigation with Three Screens

Replace App.tsx with the following starting example. It demonstrates navigation and parameter passing; students will add the form and persistent storage during the lab.

import React from 'react';
import { Button, SafeAreaView, Text, View } from 'react-native';
import { NavigationContainer } from '@react-navigation/native';
import { createNativeStackNavigator } from '@react-navigation/native-stack';
import type { NativeStackScreenProps } from '@react-navigation/native-stack';

type RootStackParamList = {
  Home: undefined;
  Tasks: undefined;
  TaskDetails: { taskId: string; title: string };
};
const Stack = createNativeStackNavigator<RootStackParamList>();

type HomeProps = NativeStackScreenProps<RootStackParamList, 'Home'>;
function HomeScreen({ navigation }: HomeProps) {
  return (
    <SafeAreaView style={{ flex: 1, padding: 24 }}>
      <Text style={{ fontSize: 26, marginBottom: 20 }}>Personal Organizer</Text>
      <Button title="View Tasks" onPress={() => navigation.navigate('Tasks')} />
    </SafeAreaView>
  );
}

type TasksProps = NativeStackScreenProps<RootStackParamList, 'Tasks'>;
function TasksScreen({ navigation }: TasksProps) {
  return (
    <View style={{ flex: 1, padding: 24 }}>
      <Text style={{ fontSize: 22, marginBottom: 20 }}>My Tasks</Text>
      <Button title="Open Sample Task" onPress={() =>
        navigation.navigate('TaskDetails', { taskId: '1', title: 'Study React Navigation' })
      } />
    </View>
  );
}

type DetailsProps = NativeStackScreenProps<RootStackParamList, 'TaskDetails'>;
function TaskDetailsScreen({ route }: DetailsProps) {
  return (
    <View style={{ flex: 1, padding: 24 }}>
      <Text style={{ fontSize: 22 }}>{route.params.title}</Text>
      <Text>Task ID: {route.params.taskId}</Text>
    </View>
  );
}

export default function App() {
  return (
    <NavigationContainer>
      <Stack.Navigator>
        <Stack.Screen name="Home" component={HomeScreen} />
        <Stack.Screen name="Tasks" component={TasksScreen} />
        <Stack.Screen name="TaskDetails" component={TaskDetailsScreen} />
      </Stack.Navigator>
    </NavigationContainer>
  );
}
Important: This sample uses React Navigation with an Expo blank TypeScript project, not Expo Router. If your existing project uses Expo Router, use its file-based navigation approach instead of mixing both systems.

Assignment: Personal Mobile Organizer (100 Points)

Goal: Extend your lab into a polished application that combines Module 7 persistence with Module 8 navigation and UX principles.

Functional Requirements

  1. Implement Home, Tasks, Task Details, and Settings screens (at least four screens total).
